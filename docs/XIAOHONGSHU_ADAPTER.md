## 网站流程

`/new/home` 自动发出 `/api/galaxy/creator/home/personal_info`；`/new/note-manager` 自动发出 `/api/galaxy/v2/creator/note/user/posted?tab=0&page=0`。

直接重放未签名请求实测返回401/406。采集器监听正常网页生成的签名响应，不保存签名算法或将捕获的请求头写入配置。

笔记管理使用内部 `div.content` 滚动容器。第一页包含置顶笔记和 `tags[].notes_count`，后续页可能为空tags，页码也不保证逐一递增。采集器由页面完成下一页请求，按唯一ID与首屏总数判断覆盖；置顶重复不会增加计数。达到页数上限返回明确的部分结果，总数发生变化或无法覆盖时不会冒充完整。

| 输出 | 页面字段 | 口径 |
| --- | --- | --- |
| read | view_count | 笔记累计观看数 |
| like | likes | 累计点赞数 |
| comment | comments_count | 评论计数，不能代替评论明细 |
| collect | collected_count | 累计收藏数 |
| share | shared_count | 累计分享数 |
| published_at | time | 后台展示的发布时间，精度为分钟 |

`visible_time` 不当作精确发布时间。短期 `xsec_token` 不写入快照、配置或日志；保存的作品URL仅含稳定笔记ID，主站实际访问可能需要登录及页面生成的导航参数。

## 评论及回复

创作后台的笔记封面会打开小红书主站详情；主站需要单独登录。采集器先核验创作后台的小红书号，再监听主站 `/api/sns/web/v2/user/me`，要求非游客、内部用户ID与小红书号均匹配。每次从本账号笔记管理取得短期导航信息，在内存构造与网页相同的详情链接。

一级评论由页面自动请求 `/api/sns/web/v2/comment/page`，滚动 `.note-scroller` 继续；二级回复点击对应父评论的“展开”，监听 `/api/sns/web/v2/comment/sub/page`。两个接口分别检查笔记ID、响应用户ID、布尔 `has_more`、游标进度和完整数量，保留根评论与实际回复目标的区别，不调用发评、点赞或删除接口。

根评论自带 `sub_comments` 预览不等于完整回复。9条样本包含7条根评论、2条回复，其中一条需额外请求。另一9条样本包含3条根评论、6条回复。当前真实样本根评论均未超过一页；一级多页和连续多页回复以隔离Chrome夹具验证，不能把夹具称为真实账号多页实测。

零评论页面不显示总数标签，要求授权响应为空且 `has_more=false`，并观察到 `.no-comments` 空状态，才认定成功。主站可见范围与总数不符、分页上限或会话失效均报错；不把删除、审核隐藏或不可见评论宣称为已获得。

逐篇实测使用38次计入预算的响应，共31条。旧生产提醒状态中该平台的一条历史评论ID，与当前同笔记响应精确一致；旧状态仅只读对账。无需改写稳定24位笔记/评论ID。提醒入口实测检查最近8篇、8页一级评论，共9条可见根评论，错误0、新增提醒0，未生成待发送邮件；历史评论按启动时间基线处理。三套快照结构校验通过。
