## 作品与指标

- `/web/api/media/user/info/`：验证 `unique_id`（为空才用`short_id`）与项目抖音号匹配，并检查绑定的内部UID。
- `/janus/douyin/creator/pc/work_list`：`status=0,count=12,max_cursor=0,scene=star_atlas` 起始，使用响应游标继续，要求总数不变且完整覆盖98条。

首页 `/web/api/creator/item/list` 的本次默认窗口只有近期3条，不用于完整目录。

`aweme_list[].aweme_id` 是字符串形式的稳定作品ID；部分旧字段 `item_id/group_id` 已经发生数值精度丢失，禁止用作主键。采集器按稳定ID连接 `items` 指标，检查两组核心计数一致。时长原字段为毫秒，保留 `duration_ms` 并转换展示秒数。

部分作品页面显示“减少作品推荐”和指标“—”，后台仍返回具体数值。采集保留审核状态和后台累计指标来源，不将“—”转成零，也不将所有作品混称为无条件公开可访问。

后台累计评论计数与主站可见评论数量存在差异：本次后台合计49，主站为55。部分差异涉及作者自身评论；差异原因尚未全部确认，不能简单归结为刷新延迟。大屏保留后台指标口径，评论监控独立使用主站完整分页结果。

## 评论与回复

旧创作后台返回加密标识，新后台返回数字标识。为避免随后台流程切换而产生身份迁移，评论统一读取主站 `https://www.douyin.com/video/<稳定作品ID>` 正常加载的数据。只查询已在当前账号作品清单中核验的作品。

- 一级评论：`/aweme/v1/web/comment/list/`。
- 二级回复：点击目标评论的展开按钮，监听 `/aweme/v1/web/comment/list/reply/`。
- 网站当前也会将请求发往 `www-hj.douyin.com`，仍限制在抖音域名及上述两个已观察到的路径。
- 使用网站正常生成的签名请求，不保存或重放签名算法。直接请求可能返回`status_code=0,status_msg=blocked`，必须判定失败，不能视为空评论。
- 检查请求作品ID、每条评论的作品ID、回复根ID、游标、总数及结束标记；区分回复根评论与实际回复目标，保留数字用户ID识别作者。
- 先完整读取一级评论，再按需要展开回复；同一次监控中的完整回复结果可复用。零评论必须有结构完整、结束明确的成功响应。
- 阻断视频媒体下载，仅加载评论所需网页资源。默认使用独立无界面浏览器，避免界面不可见导致点击不响应。
- 对明确的CDP“响应体资源不存在”错误，仅按页面刚生成的同一GET地址和请求头复核一次，计入预算且不跟随重定向；不会重试权限拒绝、限流、其他域名或写请求。地址和请求头只在内存使用。
- 评论区延迟加载时滚动到当前DOM节点，避免SSR重绘导致元素失效；同一作品、同一根评论、同一请求游标的镜像响应只计为一页。

只承诺主站当前可见的评论与回复，不声称能取回删除或不可见内容。当前生产旧提醒状态的两条抖音记录属于其他作品，不将其伪称为望获OS的逐条历史对账证据；稳定字段与旧解析器同为`cid`。旧后台的加密评论结果不写入监控状态。

## 隔离运行

私有配置为 `provider: douyin_creator`，每个账号独立会话。定时评论任务会从项目账号名单补齐身份，不依赖本轮先执行新作品发现。

```bash
PROMOTION_RUNTIME_DIR="$PWD/.runtime/local" PROMOTION_TEST_MODE=1 \
  .venv/bin/python pipeline/fetch_data.py --only 'douyin:望获OS' --max-pages 20

PROMOTION_RUNTIME_DIR="$PWD/.runtime/local" PROMOTION_TEST_MODE=1 \
  .venv/bin/python pipeline/comment_monitor.py --platform 'douyin:望获OS' --limit 8 --max-pages 20 --no-discovery
```

账号选择器用于限定联调对象；生产完整覆盖时不设置`--limit`。测试不会修改主干或生产数据，也不发送实际邮件。全项目仍需其他账号接入及七天观察。
