## 读取机制

视频号助手使用微前端。新会话中的深层链接可能先回到首页；同一个作品接口也同时被首页的5条预览卡片与20条视频目录使用。适配器不会把预览卡片当作完整目录。

流程是：验证首页短号 → 从正常网页请求获取当前会话字段 → 用已观测的只读接口和明确参数读取完整目录/评论。会话字段只在内存中使用，不保存到采集配置或公开快照。

已验证的读取路径：

- 作品：`/micro/content/cgi-bin/mmfinderassistant-bin/post/post_list`，明确使用20条/页、`currentPage`、视频类型与置顶排序参数。
- 评论及回复：`/micro/interaction/cgi-bin/mmfinderassistant-bin/comment/comment_list`，用 `lastBuff` 翻页；二级回复另带 `rootCommentId`。

这些接口可能返回HTTP 201，成功还必须满足 `errCode=0`。不会仅凭HTTP状态认定成功。

一级响应中的 `commentCount` 包含评论和回复；二级分页的 `commentCount` 可能为0但仍返回一条回复，因此按真实数组与结束标记读取。全部完成后校对总量。

对只检查一级评论的任务，不发额外的二级分页请求。线程仍有未展开回复时，给出“回复数仅为下界”标记；正式监控会重新检查这种线程，不能因下界未增长就漏掉新回复。

直接请求仅允许上述两个读取接口。采集器不调用评论发送、删除或权限修改接口，并阻止页面自动的评论状态更新请求。初期网页调查中，人工式打开评论面板观察到网站会自动发送状态更新；它不属于后续采集器的请求路径。

## 指标与身份边界

- 播放、喜欢、评论、转发按后台原始计数保存。
- `favCount` 单独留在附加指标中，尚未将其解释成收藏。收藏和下载保持未知值。
- 未取得稳定的作品公开链接时，链接留空，不把临时媒体地址当永久作品链接。
- 部分个人评论不返回用户ID；这些回复可以保存正文，但不能按昵称推断为官方回复。平台返回的作者账号ID可以精确匹配。
- 可移植会话已在本机新浏览器中验证；跨机器或出口IP变化仍需目标环境验证。

## 操作入口

```bash
# 新账号完成网页登录后，以配置短号进行双重核验并建立绑定
.venv/bin/python pipeline/provider_setup.py bind-channels --account 'wechat_channels:望获OS'

# 全量目录的只读验证
.venv/bin/python pipeline/provider_setup.py probe --account 'wechat_channels:望获OS' \
  --max-pages 20 --output .runtime/probes/channels.json
```

本地测试先设置 `PROMOTION_RUNTIME_DIR` 为当前工作树的私有测试目录，并启用 `PROMOTION_TEST_MODE=1`。详见 [本地开发说明](LOCAL_DEVELOPMENT.md)。
