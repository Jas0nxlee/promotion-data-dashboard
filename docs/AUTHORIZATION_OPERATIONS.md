# 账号授权与失效恢复操作

Docker初始化、端口和目录配置见 [Docker可视化授权](DOCKER_AUTHORIZATION.md)。本页说明日常操作，不替代真实部署环境的账号验收。

## 宿主机没有初始化工具时

可以直接使用登录镜像内的Python和htpasswd，不必给宿主机安装这些依赖。先准备 `.env` 并构建镜像，然后在交互终端运行：

```bash
docker compose --profile login build login
mkdir -p .runtime
docker run --rm -it --network none --user "$(id -u):$(id -g)" \
  --entrypoint python -v "$PWD/.runtime:/setup" \
  promotion-dashboard-login:latest /app/scripts/init_authorization.py \
  --auth-dir /setup/authorization --provider-dir /setup/provider-config \
  --sessions-dir /setup/sessions
```

已有本机旧配置时，在命令末尾加 `--migrate-provider-file /setup/providers.json`。新文件会改用portable会话并去除本机调试连接，原文件保持不变。初始化完成后再启动 `login`；该初始化容器不运行采集、桌面或网络服务。以后也可用相同容器命令加 `--replace-password --prompt-password` 重置口令。

## 首次授权

1. 打开管理地址并输入管理员凭证。默认地址为 `http://127.0.0.1:18762/`；远程机器先通过SSH转发访问。
2. 在账号清单选择目标账号，点击“打开登录”。页面显示服务器浏览器和授权截止时间。同一桌面一次只处理一个账号，其他账号的正常采集不受影响。
3. 在该窗口扫码或使用平台正常登录方式。小红书需在创作后台和主站两个标签页登录同一个账号；安全验证由运营人员正常完成。
4. 点击“已完成登录，验证并保存”。程序先核对项目绑定的账号ID，导出独立候选会话，再使用新浏览器恢复会话、验证完整内容与必要指标。四个评论明细平台还会验证代表作品的评论/回复读取。
5. 验证成功才替换正式会话并恢复该账号采集。账号授权状态与整体采集验收分开显示：例如完整但为空的评论样本允许保存登录态，不伪称已经验证二级回复。

公开采集的CSDN、电子发烧友、搜狐和今日头条不需要扫码。公众号官方API配置也不通过网页扫码续期，应维护其独立API授权。

授权服务只保存会话、配置、验证证据和请求预算，不更新大屏快照、评论基线或邮件队列。正式调度任务随后读取新会话并更新数据，不需要运营人员电脑持续开机。

## 登录失效后

- 实际采集发现登录失效或账号身份不一致时，账号进入“需要重新授权”；后续自动任务暂停访问该账号，保留已有快照和评论状态。
- 点击该账号“重新授权”，重复正常扫码与验证保存。旧的成功会话在新候选验证完成前不会被覆盖。
- 若登录了错误账号、目录不完整、关键指标不足或小红书主站未登录，面板显示原因，允许继续完成登录后重试。仅打开窗口、导出文件或取得部分目录不算授权完成。
- 授权窗口有效期为30分钟。取消、超时或浏览器关闭会释放桌面，并继续等待重新授权；验证保存期间禁止重复提交或手工取消。
- 手工CLI的完整 `probe` 也可以重新验证并恢复已失效的会话；它不能抢占正在进行的可视化授权。导出、绑定和评论验证本身不会解除失效暂停。

## 服务重启和故障

配置、会话与验证证据提交前会保存私有事务备份。服务中途退出时，重启会回收经进程参数核验的本次浏览器/验证进程，并回滚未完成事务；已经完成的授权保留。新的授权操作不会被旧操作或迟到的失败结果覆盖。

如果存储权限或空间问题导致回滚失败，事务记录和备份会保留，服务不会开始新的授权覆盖它们。修复存储后重启授权服务，让恢复流程完成；日志和管理页面会报告恢复未完成。

更新项目账号名单或改绑稳定ID后，应重启授权服务并重新验证目标账号。不要把同名账号视作同一身份。

## 管理员口令重置

使用初始化工具的 `--replace-password --prompt-password`，保持原账号配置不变。随后单独重启 `login`，关闭旧的管理页面连接和已建立的远程桌面连接；不会重启采集器。

```bash
python3 scripts/init_authorization.py --replace-password --prompt-password
docker compose --profile login restart login
```

## 本地验证边界

隔离单测覆盖账号/操作ID匹配、来源和CSRF检查、候选会话恢复、失败回滚、超时、提交中断以及新旧授权代次隔离。Docker冒烟验证网关认证、桌面和WebSocket、挂载与重启；授权流程端到端测试使用模拟平台及真实Chromium会话：测试入口为空白页，目标域名强制指向容器本地地址，业务页面请求全部由夹具响应或拦截；没有使用真实账号或会话。这是目标域名与浏览器请求隔离，不宣称容器全面断网。

这些测试验证容器机制，不代表已经在生产服务器完成真实平台扫码。实际部署后仍须逐账号验证服务器IP、登录会话、权限及采集范围。
